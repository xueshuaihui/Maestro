# 2026-11-20

## 修复用户级 DSH 模型路由（acp profile 空 patch → 全部会话 MISSING_CREDENTIAL）

**症状**：DSH 会话每条 turn 都报 `llm-deepseek: no API key for provider route "deepseek-official"`（`MISSING_CREDENTIAL`）。

**根因**：本机 `~/.dsh/.credentials.yaml` 只有账号登录凭据（`deepseek-account-platform/device`、`.../default`），
没有 `DEEPSEEK_API_KEY`；而 acp bundle 自带默认路由是 `deepseek-official`（API-key 组件 `@deepseek-ai/dsh-llm-deepseek-api-key`）。

**处置**：
- `~/.dsh/profiles/acp/cordis.patch.yml` 原本是空数组 `[]`（217 字节模板），补上 `agent-default-model` 与 `acp`
  两条 → `provider: deepseek-account` / `model: deepseek-flash`。备份 `.bak-20261120`。
  （`acp` 行优先级高于 `agent-default-model`，只改一处无效 —— 与 I1.12 AC-01 证据帧一致。）
- `~/.dsh/profiles/desktop/cordis.patch.yml` **未改**：其 `agent-default-model` 已于 11-19 23:04 指到
  `deepseek-account`/`deepseek-flash`；但同文件里 `ui-settings: enabled: false` 会隐藏界面设置页
  （用户因此找不到「模型设置」入口），按用户意愿暂不动。

**验证（真实宿主闭环，非 mock）**：隔离 `DSH_HOME` + 复制 acp profile/凭据 → `initialize` ok、
`session/new` ok、`session/prompt` → `{"stopReason":"end_turn"}`，模型回「收到。」，
stderr 出现 `[llm-deepseek-account] model listing from https://api.deepseek.com/models loaded 2 model(s)`
（证明走的是 account 路由，不是 api-key 路由）。验证后隔离目录与复制的凭据已删除。

**环境事实补充**：`--profile desktop --dump-config` 被拒绝（`profile "desktop" is managed exclusively by the
Electron application`），desktop profile 无法用 CLI dump 核对；acp profile 可以。
acp profile 的 patch 里 `deepseek-flash` 与 `deepseek-v4-flash` 都可用（后者是 acc12-perf-pilot 的写法），
本次统一用 `deepseek-flash`。改完配置要**新开会话**才生效，旧会话保留原路由记录。
