# 2026-11-25 工作日志

## 工作流画布从只读架子补成可用编辑面（commit `a5e0f0a`，本地未发版）

用户反馈「画布啥都看不到也不能编辑」。Grounded 核对两个项目后确认根因并修复：

- **三处渲染缺陷**：`pages.js` 把 layout 的 `{kind,ctrl}` 对象直接写进 SVG `d` → 连线全不可见；节点只画裸 id 不用算好的中文 `text`；工作流选择器只列 `/workflows` 三个内置模板，Studio flow 完全选不到。
- **两处能力缺口**：定义态投影按 AC-30 不含运行时状态，Studio `runs[].stages[].status` 没接上；画布节点/边无 `data-action`，HTTP 无编辑 action。
- **修复**：新增 `studioCanvas()`（Studio flow 投影带 status/progress，**冻结的 YAML/内置投影形状逐字不动**）、`canvasEdgePath()`、六个 `/studio/action`（`flow.update`/`stage.add|update|remove`/`flow.edge.add|remove`），域函数统一走 `editFlow` 草案 + `validateFlow` 门禁；UI 加中文标签/状态色/进度条/动态 viewBox、点选改名删阶段、连线模式增删依赖、节点拖拽存 localStorage。

### 关键坑（可复用）

1. **桌面 purity 扫描禁止 `editor` 字面量**：新模块命名 `canvas/editor.js` 直接把 4 条 31 词扫描撞红（import 路径即命中），改名 `drag.js` 后归零。新增桌面文件前先过 forbid 词表。
2. **`mountApp` 作用域内没有 `state` 变量**：painter 用 `app.state()`，新写的 `runCanvasEdit` 曾误用裸 `state`，导致 HTTP 已落盘但 `loadCanvas` 从未执行（真浏览器实测：磁盘 3 阶段、DOM 仍 2 节点）。改用 `app.state()`。
3. **连续编辑会被旧请求回退**：两次 `/studio/action` 后的 `/workflows/:id/canvas` 竞态，旧帧后到覆盖新 DAG；加单调 `canvasLoadSeq`，非最新序号直接 return。
4. CDP 拖拽前必须 `scrollIntoView()`，否则 `elementFromPoint` 为空、pointerdown 打不到节点。
5. `STUDIO_TEXT` 无键数冻结；冻结的是 `UI_LABEL_KEYS`（精确集合）与 `DESKTOP_V2_LABEL`，新增画布文案一律走 `STUDIO_TEXT`，由 `ctx.st()` 读 `/studio/labels`。
