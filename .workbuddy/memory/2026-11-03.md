### 关键事实（后续迭代必读）

- 本机 DSH 装在 `%LOCALAPPDATA%\Programs\DeepSeek Harness`（CLI 0.2.1-rc.5，Electron 以 node 模式跑 app.asar/cli.js），PATH 里没有 dsh；ACP 需另装 `dsh-acp-server@0.14.4`。
- `dsh-acp-server` Windows 两个坑：bin 用 `import(join(...))` 触发 ERR_UNSUPPORTED_ESM_URL_SCHEME；bootstrap 用 spawnSync('dsh') 无法解析 .cmd。绕行器在 `spike/dsh-launcher/`。
- 无模型凭据时，可在隔离 DSH_HOME 的 `profiles/acp/cordis.patch.yml` 注入 `dsh-acp-server/test/mock-llm` 并把 `agent-default-model` 指到 mock/mock-1，即可跑真实 ACP turn（官方 e2e 同款做法）。
- Cursor 只装了 IDE（3.22.12），**没有 cursor-agent CLI**，`agent acp` 不可用 → VP-5 阻塞。
- 真实 DSH 的 `tool_call_update` 不含 diff、不含产物指纹；acp profile 下 bash 工具报 UNKNOWN_TOOL。证据模型必须由核心自算指纹。
- 发现：HTTP/SSE 上 `session/load` 回放帧与响应跨通道乱序，适配器必须 drain-quiet（idle 40ms），否则回放漏到下一个 turn。真实 HTTP 形状：POST /acp 只回 202，GET /acp/stream 收 SSE，`acp-connection-id` 做亲和。
- DSH 未知会话错误码是 -32602（不是 ACP 习惯的 -32002），降级链要同时认。
