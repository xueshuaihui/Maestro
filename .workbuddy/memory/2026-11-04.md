- 根因（重要）：不是宿主缺能力。dsh-base 组合层对 shell 工具做平台条件挂载：`tool-bash` 带 `disabled: process.platform === 'win32'`，Windows 上由 shell 工具的另一实现顶替；`tool-fs` 无条件挂载，注册 `read/write/edit/read_image`。阶段零 mock 的 CALL_TOOL 硬编码 `name="bash"` → `UNKNOWN_TOOL`。结论：探针 bug，不是能力缺失。
- 顺带查明：DSH 0.2.1-rc.5 的 acp profile 模板**自带** ACP server（`@deepseek-ai/dsh-acp-app`）；第三方 `dsh-acp-server@0.14.4` 用 patch 把内置行 disabled 才独占 stdio，那两个 Windows 包级缺陷属第三方包，非 DSH 本身。I1.1 可评估直接对接内置 app 以省掉 shim。
- 本机 dsh CLI 入口（无 dsh.cmd）：`ELECTRON_RUN_AS_NODE=1 "<安装目录>/DeepSeek Harness.exe" "<安装目录>/resources/app.asar/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js"`，可 `--profile acp --dump-config`。asar 读取：头部 16 字节，JSON 长度在 offset 12，数据从 16+jsonSize 起。
