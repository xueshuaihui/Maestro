   `%LOCALAPPDATA%\Programs\DeepSeek Harness\DeepSeek Harness.exe` + `resources/app.asar/dsh/node_modules/@deepseek-ai/dsh/lib/bin.js`，env 加 `ELECTRON_RUN_AS_NODE=1`，args 加 `--profile acp`。
   ⚠️ 纯 Node 的 `fs.access` **看不到 asar 内部路径**，所以 `probeDshInstalled()` 的 `fs.access` 校验会误报「未找到 bin.js」——exe 其实能正常执行该 asar 路径。要验证一律用 `--version` 实跑。
2. **隔离 DSH_HOME**：`%TEMP%/<rand>/dsh-home`，复制 `~/.dsh/profiles/acp` 与 `~/.dsh/.credentials.yaml`，结束删（只删自己复制的那份）。用户 `~/.dsh` 一个字节都不动。
3. **provider 必须覆盖两处**（acp profile 的 patch 层）：
   `agent-default-model` → `{provider: deepseek-account, model: deepseek-flash}` 且 `acp` → `{provider: deepseek-account, model: deepseek-v4-flash}`。

4. **ACP 帧是 NDJSON**（按 `\n` 切），`initialize` → `session/new {cwd, mcpServers:[]}` → `session/prompt`；首事件取 `session/update` 或该 id 的 response。

### 过程教训

- 用 `node -e` 写内联核对脚本时，**反引号会被 bash 当命令替换**（`USAGE_LINES` 那类含反引号的字符串直接炸成 `command not found`），一律改用无反引号的纯文本匹配串。
- 兼容 CRLF 仓库：`git add` 会打 LF→CRLF 警告但不影响提交；恢复被测试覆盖的历史证据仍用 `git -c core.autocrlf=false checkout-index -f -- <路径>`。
