### 1. 「正在连接守护进程…」卡死（根因是「文件存在 = 活着」）
- Rust `spawn.rs` 新增 `core_answer()`（发 `core.ping`、限时读回包）、`pid_alive()`（`/bin/kill -0`）、
  `core_answers()`、`clear_stale()`（删 `.orch/desktop.json` + `core.sock`，命中发 `daemon-stale-cleared` 探针）、
  `retire_core()`（发 `core.stop` 限时等 socket 消失）。
- `channel_ready()` 取代「文件存在」：记录 + pid 存活 + `/ui/labels` 用记录里的 token 应答 +
  `core.ping` 的 generation/pid 与记录一致。
- `main.rs` 新增 `ensure_daemon()`：健康就 adopt、活着但不响应先 retire 再清再拉起；`bind_project` 同 root
  重试不再直接返回 0 而是重走 ensure；`ui_navigated` 防止每次轮询重导航。
- **`startup_status` 改 `#[tauri::command(async)]`**：同步命令跑在主线程，探活最长 1.6s 会把窗口一起冻住，
  正是用户抱怨的症状。
- 首启页 `shell-ui/index.html` 改自调度 `setTimeout`（原来 `setInterval` 会在真实往返下叠加请求），25s 预算。
- **端到端**：`verify-shell-boot.mjs` 新增「SIGKILL 核心留陈旧记录 → 二次启动」场景，真实 `.app` 11/11。

### 本批踩到的门禁坑（值得记住）
- **`desktop/ui` 也有 CJK / 31 词纯净扫描**：我加了 `st('UI_CANVAS_FIT','适应窗口')` 与全角冒号 `：`、
  变量名 `editor`，三条红线各红一次。前端兜底文案必须是 ASCII；分隔符用空格或 `·`。
  自查用 python 正则 `[\u3000-\u303f\u4e00-\u9fff\uff00-\uffef]` —— **macOS 的 `grep -P` 不可用会静默返回空**。
- **`node --test` 必须注 `NODE_ENV=test`**：`/__test__/graph/pulse`、`/__test__/window-probe` 等接缝按该变量注册，
  否则 wp13/wp14 会假红 4~7 条（我一开始就把这当成回归，白查一轮）。
- **`npm run desktop:build` 会被沙箱批量删除保护拦住**（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，193 个文件 > 50 阈值）：
  把旧 `Maestro.app` 改名成 `Maestro.app.pre-<用途>-<ts>` 让位即可，这也是历史上那堆 `pre-*` 目录的来历。
- 全量 2044 条：2033 pass / 8 fail / 3 skip。8 条差集 = 6 条本机环境红（`/private/var` vs `/var`、
  `D:\` 盘符用例、`copyToBackup` 的 `EIO`、`AC-43 会话重建`、`core.stop` 收敛、`早返回` 1079ms）
  + 1 条负载 flake（`自动拉起 detached`，独占复跑 6/6 绿）+ 1 条「未提交 diff」型（`AC-23 #3` 边界用例，
  提交后 5/5 绿）。**新增红 = 0**。
