## 用户实测爆炸：beta.4「一直处于连接状态」→ 三处阻断缺陷（同日 hotfix）

**教训（最高优先级）**：域层 11/11 + HTTP 通道 16/16 + 包内路由 200 **全部漏掉了浏览器里的入口问题**。
页面文件进包 ≠ 用户点得到；必须有一层"真实浏览器点击"验证。

### 三处根因（都是本次新代码）

1. `desktop/ui/app.js` `setView()` 白名单漏 `studio` → 导航项渲染但点击不切视图，iframe 从未挂载。
2. 壳把 token 写 **sessionStorage**（`TOKEN_STORAGE_KEY = 'maestro.desktop.token'`，app.js:3981），
   `studio.js` 只读 **localStorage** → iframe 无凭据。修法：抽 `desktop/ui/studio/token.js`，
   优先级 URL → sessionStorage → localStorage。
3. `studio.js render()` 的 `app.replaceChildren()` 把 `#loading` 删了，后续 `load()` 再写它 →
   点"一键演示"只建出 23 角色就抛异常，流程/团队/运行全不发生。修法：`setLoading()` 容错。
   同批修 `DEMO_DONE` 模板未填占位符。

### 新增验证层

`npm run verify:desktop` → `scripts/verify-desktop-boot.mjs`：
真实 `serve-entry.js --desktop` 启动 + 无头 Chrome/CDP（`--no-sandbox` 必加），
16 项覆盖冷启动、token 落点、导航点击、iframe 内容、按钮一键配置、无未捕获异常。
`verify:release` 现在串联 core → ui-flow → desktop 三条。

### CDP 脚本坑

- 导航项监听的是 **pointerdown** 捕获（`app.js:3548`），不是 click；合成事件要
  `dispatchEvent(new PointerEvent('pointerdown', {bubbles:true,button:0}))`。
- `waitFor` 的 predicate 返回对象即使全 0 也是 truthy，必须显式判计数 > 0 才返回对象，否则假绿/假红。
- Chrome headless 必须带 `--no-sandbox`，否则 CDP 端口出现但 `/json/list` 空响应并挂住。
- 本机 Intel Mac 跑不了 arm64 包内 node；本地 `npm run desktop:build` 可出 x64 包。

### 重新发版事实

- 标签删了重推 → `v0.0.1-beta.4` → `7078c65`；CI `45401521008` Windows 首轮被
  `AC-31`（4s 等待上界，duration 4215ms）拦下，重跑失败作业后四作业全绿。
- **删 tag 会让 Release 变 draft，CI 只 `--clobber` 不重新 publish**：必须
  `PATCH /releases/{id}` 设 `draft:false` + `prerelease:true` + `target_commitish` **完整 sha**

## 「环境缺口」口径纠正：本地搭环境 = A1/A5 真实宿主全取证（同日晚）

**用户追问「环境缺口？在本地搭建环境呢？」→ 复核证明原口径错误**：本机没 CLI ≠ 装了也不能跑。
`npmmirror` 通（200/1.4s）、Node 22 在，`npm i opencode-ai@1.19.6` 15s 装好（`--registry=https://registry.npmmirror.com/`）。

### 真正卡住的两处产品缺陷（不是环境）
1. **ACP 启动方言**：`probeAcp` 默认 `--acp` flag，opencode 用 `acp` 子命令（`--acp` → exit 1 / acp:false；
   `acp` → acp:true/protocolVersion:1）。修法：`acpArgsFor(finding)` 按 `cli_id` 查 known 表，
   known 表给 opencode 加 `acpArgs:['acp']`；finding / user_config / registry 全链路带 `acp_args`。
   **别硬编码单一 flag** —— 各 CLI 入口不同（子命令 vs flag）。
2. **能力 wire shape**：真实帧把能力放 `agentCapabilities.sessionCapabilities:{close:{},fork:{},...}`（对象），
   旧解析只认 `sessionCapabilities:[...]` / `capabilities.session` → 取空。修法：对象取 keys、数组取元素，
   `capabilities` 也改从 `agentCapabilities` 取键。

### 取证结果（证据分级：本机真实 CLI + 真实模型，非 mock）
- `cli add` → `cli probe opencode` → 「ACP 支持」；registry 落盘 `acp:true/version:1.19.6/capabilities:[close,fork,list,resume]/connected`。
- `initialize → session/new → session/prompt → agent_message_chunk("PONG") → end_turn`，inputTokens 7637/outputTokens 4。
  **opencode 自带免费模型 `opencode/big-pickle`，无需用户凭据** —— 连"模型凭据缺口"都能本地补。
- 改动文件：`src/adapter/cli-discovery/{discover,index,known-agents,probe}.js`、`src/cli/cli-discovery.js`
  + `test/wp16/cli-probe.test.js`（+2 条）+ 文档 `beta.4-release.md` §12 / `index.md` 3 处口径。
- 验证：wp16 51/51、verify:core 11/11、purity 零命中、全量 2003/1991pass/10fail（失败全在恢复/性能/core.stop/task-loop 等
  与本次零交集的既有脆弱点，独占复跑证伪中）。

### 纪律沉淀
- **"观测不到"要先分清是"环境没装"还是"探针不支持"**。前者搭环境即可，后者是产品 bug。

## 重发 v0.0.1-beta.4（同日第四轮）

用户「重发 .4」。背景：tag 停在旧 hotfix `7078c65`，访客下载不含当天 A1 修复。

### 关键路径决策（避免前次坑）
- **删 Release + 删 tag → 重推**，而不是只删 tag。只删 tag 会让 Release 变 draft，
  CI publish job 对已存在 Release 只 `upload --clobber`，不重新 publish、不改 target_commitish
  → 产物换了但 Release 元数据仍指旧提交。
- 命令序：`gh release delete v0.0.1-beta.4 --yes` → `git push origin :refs/tags/v0.0.1-beta.4`
  → `git tag -d` → `git tag -a <tag> -m "..." <新commit>` → `git push origin <tag>`。
- tag 是 annotated object（rev-parse 显示 tag object sha `25ce86d`，`^{}` 解引用到 commit `bd37df9`）。
- 文档记录放在 tag 之后的独立提交 `4df980a`（符合「被验证提交之后的独立提交」纪律）。

### 发版前门禁差集归因方法
- 本机 gate 6/7，2 条意外红：`copyToBackup`(EIO≠ENOENT)、`AC-43 会话重建`(running≠escalated)，
  低负载单独跑仍红 → 用 `git worktree` 拉旧 tag 提交 `7078c65`（CI 上次全绿同提交）复跑同样红
  → 判定本机沙箱固有红；CI Windows job 门禁 PASS 佐证。不阻塞发版。

### 结果
- CI run `45421794691` 四 job 全绿（三平台构建+冒烟+汇总发布）。
