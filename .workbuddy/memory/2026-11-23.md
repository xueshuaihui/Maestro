## beta.3：用 CDP 直连真实窗口做交互验证（用户反馈「侧栏有时候切不动」）

### 真机验证方法论（本轮最有价值的新手段）

Windows 上没有 computer-use 技能时，**给 WebView2 开远程调试端口直连**是最接近真人的验证方式：

```bash
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9222 --remote-allow-origins=*' \
  "/c/Users/xuesh/AppData/Local/Maestro/Maestro.exe"   # 用 bash run_in_background 起，不要用 PowerShell Start-Process
```

- `Start-Process` 起的 GUI 进程会随工具会话结束被杀；必须用 Bash `run_in_background` 前台跑。
- 连 `http://127.0.0.1:9222/json/list` 拿 `webSocketDebuggerUrl`，Node 22 自带 `WebSocket` 可直接连，
  项目不需要装 `ws` / `playwright`。
- `Input.dispatchMouseEvent`（mousePressed/mouseReleased）是**真实鼠标事件**，会走浏览器的命中测试，
  和 `element.click()` 完全不同 —— 后者绕过了"按下与抬起是不是同一节点"这条规则，测不出丢 click。
- `Page.captureScreenshot` 出 base64 PNG，落盘后用看图工具核对视觉。
- 安装版把 `desktop/ui/**` 与 `src/**` **解包在磁盘上**（`%LOCALAPPDATA%\Maestro\`），
  改完直接 `cp -r desktop/ui/. <安装目录>/desktop/ui/` 再重启即可验证，不必等 CI 产物。
  改 `src/cli/labels.js` 必须重启（daemon 进程要重新 require），改 `desktop/ui/**` 只需刷新。
- **重启坑**：WebView2 用户数据目录会被残留的 `msedgewebview2.exe` 占用，重启太快会 panic
  `HRESULT(0x800700AA) 请求的资源在使用中`。等 10 秒再起，或按命令行筛 `com.maestro.desktop` 杀。
- **daemon 是 detached 子进程**：`taskkill Maestro.exe` 之后 `serve-entry.js` 还活着占着端口，
  必须按命令行 `grep serve-entry` 一并清理，否则新实例行为诡异。
- tag 推送遇到 `CONNECT tunnel failed 502` 时，**用 API 创建 ref 可以绕过去**：
  `POST /repos/{o}/{r}/git/refs {"ref":"refs/tags/vX","sha":"<full sha>"}`，
  实测会正常触发 `push` 事件与 release 流水线。

### 关键口径

- **文案键全集断言不要写死总数**：现在是 `312 + V2.length + Object.keys(ROLE_LABEL).length`，
  加表/加键都自动跟随，判据仍是「精确集合相等」，不放松成子集。
- **`hidden` 属性打不过模块自己的 `display`**：凡是 `display:flex/grid` 的元素，隐藏一律用 `style.display`。
- **「实时帧重建 DOM」是桌面壳应用的通病**：任何"按住—抬起"类交互（点击、双击、拖拽、双击标题栏）
  都会被它打断。远程调试 + 高频连点是最省事的证伪方式。
- Windows 本地全量跑不完（30 分钟只到 168 例，`HANDOFF_BACKFLOW_INCOMPLETE` 之后疑似长等待）：
  继续用「只跑受影响文件 + 对照基线红名单」的口径，别等全量。
- 真机口径结果：九项导航 9/9、9 项×3 轮 60ms 连点 **27 次 0 失败**、⌘K 搜索跳转、
  新建表单选中态/输入保留、画布三模板切换（1→2→3 节点）、`window.onerror` 0 条。
