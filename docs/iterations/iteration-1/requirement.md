## 一、背景与问题

### 1.1 现状与问题

我是这个工具的唯一使用者，也是唯一编排者。现在要把一件事交给 DSH 做，流程是这样的：开一个终端、`cd` 到工作目录、敲 `dsh`、等它想、看它输出、自己判断有没有做完、自己去翻产物落在哪。

一件事还能忍。一旦有两件事要同时推进，就开始失控：

- **不知道哪个会话在干活**。两个终端窗口，一个在跑、一个卡在等确认，我从标题栏看不出来。
- **任务之间靠手工搬上下文**。上一个任务写出来的东西，我得自己复制路径、描述要求，再贴给下一个。
- **关掉终端就等于失忆**。重启之后刚才跑到哪一步、产物在哪、哪一步失败了，全靠回忆。
- **失败只有一句话**。`error` 或者干脆没输出，我得自己去猜是宿主挂了、会话没了、还是任务本身错了。

阶段零已经证明这条路技术上是通的：真实 DSH 上单轮 72ms 完成、5 个会话并发 149ms 且零串台、ACP 事件足以推断"目标已接受"（63ms）和"正在执行"。但那是**脚本级验证**——跑完就散，没有东西在持续记录状态，也没有东西替我做"东西交给谁了、对方接没接、做完没有"的判断。

**不解决会怎样**：后面每一个工作流（编码闭环 I1.2、非编码闭环 I1.3）都建立在"核心能可靠驱动会话、并且知道现在是什么状态"之上。这一步不稳，后面加角色只是把手工拼装变成更复杂的手工拼装。

### 1.2 目标与成功衡量

| # | 指标 | 目标值 | 怎么量 |
|---|---|---|---|
| 1 | 从发起任务到看见"执行中" | ≤ 5 秒（DSH 已预热，不含冷启动） | 命令输出时间戳，10 次取最大 |
| 2 | 跑完一个单节点任务的手工操作次数 | 1 条命令，0 次手动操作宿主终端 | 人工计数 |
| 3 | 会话状态与真实执行的一致率 | 抽查 20 次，≥ 2 秒的错标 0 次 | 对照宿主自身输出核对 |
| 4 | 交接包完整走完 已构造→已完成 | 连续 10 次任务，10 次完整 | 状态记录逐条核对 |
| 5 | 重启后能查到的上次状态 | 节点、会话、交接包、事件 4 项 100% 可查 | 杀进程后重开核对 |

### 1.3 范围

**范围内（本次让用户获得的新能力）**

1. 一条命令发起一个「单角色 · 单节点」任务。
2. 核心创建 ACP 会话、投递任务、订阅执行事件（stdio，只接 DSH）。
3. 6 个会话状态归一化，并在用户可见处正确切换。
4. 交接包状态机最小实现（7 个状态都有定义与触发路径，本迭代实际只走 `created → delivered → accepted → consumed`）。
5. 节点状态、会话状态、交接包状态与事件记录落盘，重启后可查。

**范围外（本次不覆盖，逐项注明归属）**

| 不做的事 | 留给谁 |
|---|---|
| 多角色、多节点、工作流引擎与路由 | I1.2 |
| 缺陷/驳回回流、轮次计数、升级生成 | I1.2 |
| 证据门禁、产物隔离（worktree / 版本化文件区） | I1.3 / I1.7 |
| 会话恢复（`resume` / `load`）、崩溃后继续执行 | I1.8 |
| 完整 CLI 命令集（`status` / `log` / `graph` / `attach` 等） | I1.4 |
| 桌面应用、看板、角色流程图、通知 | I1.10a / I1.10b |
| 审批的图形化操作 | I1.11（本迭代只保证"等待审批"状态**可见**） |
| Cursor、WorkBuddy 接入 | 阶段二 / 阶段三 |

> **关于"用户界面"**：I1.1 **没有图形界面**。用户看到的是命令行输出 + `.orch/` 下的状态文件。这是刻意的取舍——先把状态模型在真实宿主上验证到可信，再谈怎么呈现。图形界面在 I1.10a。

## 二、具体功能细节（用户视角）

### 2.1 功能总览

| 功能点 | 谁在用 | 解决什么问题 | 本次交付程度 |
|---|---|---|---|
| **A 发起单节点任务** | 编排者 | 不用再手工开终端敲 DSH、盯输出 | 一条命令跑通单角色单节点；角色与节点用最小配置，不写工作流 |
| **B 看会话在做什么** | 编排者 | 不知道会话是在想、在调工具、还是在等审批 | 6 个状态全部归一化，命令行与状态文件可见；无图形指示器 |
| **C 看交接包走到哪** | 编排者 | 分不清"交出去了""对方接了""做完了" | 7 状态机落地，本迭代走通 4 个主状态；异常 3 状态有定义与判定，不做自动重试 |
| **D 出错时看得懂** | 编排者 | 失败只有一句 `error`，得自己猜 | 四类失败可区分：目标忙 / 会话失效 / 审批被拒 / 执行失败 |
| **E 关掉再打开还在** | 编排者 | 重启后一切归零，靠回忆 | 状态与事件落盘可查；明确标"上次中断"，不自动重跑 |

> 编号说明：本迭代有 5 个功能点，故用 2.2~2.6；模板中的「功能之间的衔接」与「业务规则」顺延为 2.7、2.8。

### 2.2 A 发起单节点任务：用户能做什么，看到什么

- **使用角色**：编排者（当前就是我自己）
- **使用场景**：手上有一个边界清楚的小任务，例如"写一段 200 字的产品说明并落盘"，想交给一个角色在 DSH 上跑完
- **用户操作**：执行一条命令，指定工作目录和任务描述。不需要写工作流文件，不需要手工开 DSH 终端
- **预期效果**：命令输出依次出现——
  1. `会话已创建 sess-xxxx`
  2. `任务已投递`
  3. `执行中 · 已运行 3s`
  4. `已完成 · 耗时 1m12s`

  同时 `.orch/instances/<id>/state/` 下出现节点状态、会话状态、交接包状态三个文件
- **异常情况**：
  - DSH 起不来 → 输出 `无法启动 DSH：<原因>`，**不进入**"执行中"，不留半截会话
  - 工作目录不可写 → 输出 `工作目录不可写：<路径>`，命令以失败退出
  - 任务投递被拒（目标忙）→ 输出 `目标正忙，本次未投递`，**不谎称已投递**
- **边界说明**：一次只跑一个节点。多节点并行、节点间依赖、条件分支都不在本迭代

### 2.3 B 看会话在做什么：用户能做什么，看到什么

- **使用角色**：编排者
- **使用场景**：任务跑起来了，我想知道它此刻是在思考、在调工具、还是卡在等审批
- **用户操作**：盯着命令输出（实时刷新），或事后翻状态文件
- **预期效果**：会话状态在 6 个值之间正确切换，且都带人话说明——

  | 我看到 | 意味着 |
  |---|---|
  | `空闲` | 会话已建好，还没接到任务 |
  | `执行中 · 已运行 3m` | 正在推理或输出 |
  | `执行中 · 调用工具（写文件）` | 正在调工具，显示工具名 |
  | `等待审批：git_push` | 停在一个需要我点头的动作上 |
  | `等待校验` | 已产出，等核心校验或等下游接收 |
  | `已升级待人工` | 核心判定需要我介入 |

- **异常情况**：宿主长时间没有任何新动静 → 仍显示 `执行中`，并附 `已运行 8m · 无新事件`。**不擅自判定失败**（阶段零实测：取消要 4.3 秒才生效，贸然判定会把还在跑的当成挂了）
- **边界说明**：会话状态只更新"这个会话在干什么"的指示，**不改变节点处于哪个阶段**。取消或关闭后，该会话从列表消失或回到`空闲`。`已升级待人工` 在本迭代只有定义与显示能力，**触发路径由 I1.2 提供**（本迭代不会真的产生升级）

### 2.4 C 看交接包走到哪：用户能做什么，看到什么

- **使用角色**：编排者
- **使用场景**：我想分清三件事——"东西交出去了吗""对方接了吗""对方做完了吗"
- **用户操作**：看交接包列表（命令行）或状态文件
- **预期效果**：一个交接包按顺序显示，每步带时间戳——

  ```
  HO-001  已构造   10:30:02
  HO-001  已投递   10:30:02
  HO-001  已接受   10:30:05
  HO-001  已完成   10:31:14
  ```

- **异常情况**：
  - 目标拒绝 → `已拒绝`，并附拒绝原因（例如审批被拒）
  - 目标一直不接 → 超过等待时限后 `已过期`，并提示"需要人工处理"
  - 宿主不在线 → `待投递`，**不显示成**"已投递"
- **边界说明**：本迭代只做状态与判定，不做自动重试、不做升级生成（那是 I1.2）

### 2.5 D 出错时看得懂：用户能做什么，看到什么

- **使用角色**：编排者
- **使用场景**：任务没跑成，我需要知道该怪谁、下一步做什么
- **用户操作**：看失败提示
- **预期效果**：四类失败能一眼分开——

  | 我看到的提示 | 真实含义 | 我该做什么 |
  |---|---|---|
  | `目标正忙，本次未投递` | 那个会话正在跑另一个任务 | 等它空下来或换会话 |
  | `会话已失效，需要重新创建` | 会话被关了或根本不存在 | 重跑，会新建会话 |
  | `审批被拒绝，任务中止于 <步骤>` | 我（或规则）拒绝了一个动作 | 检查审批策略 |
  | `执行失败：<宿主原文>` | DSH 报错了 | 看原文 |

- **异常情况**：宿主返回没见过的错误 → 原文透出，前缀 `未知错误：`，**不吞掉、不改写**
- **边界说明**：不做自动重试、不做降级链（I1.2 / I1.8）

### 2.6 E 关掉再打开还在：用户能做什么，看到什么

- **使用角色**：编排者
- **使用场景**：任务跑到一半，我关了终端，或者机器重启了
- **用户操作**：重新打开，查看实例状态
- **预期效果**：能看到上次的节点状态、会话状态、交接包状态、以及完整事件记录；未完成的任务明确标 `上次中断`，并说明停在哪个状态
- **异常情况**：状态文件损坏 → 提示 `状态不可读，已备份为 xxx.corrupt`，**不静默清空**
- **边界说明**：不自动恢复执行、不重新接回原会话。恢复能力在 I1.8

### 2.7 功能之间的衔接：走完一遍是什么样

我把这五个功能串起来跑一遍，体感是这样的：

1. 敲一条命令。两秒后屏幕上出现 `会话已创建 sess-7f3a`，紧接着 `任务已投递`。
2. 状态跳成 `执行中 · 已运行 1s`。我可以去干别的，回来瞄一眼。
3. 半分钟后变成 `执行中 · 调用工具（写文件）`。我知道它在落盘，而不是在原地空转。
4. 再过一会儿变 `等待校验`。这时我去看交接包：`已投递 10:30:02 → 已接受 10:30:05`。
5. 最后状态 `已完成 · 耗时 1m12s`，交接包 `已完成 10:31:14`。事件记录里能顺着时间戳把每一步重放一遍。
6. 如果我中途关了终端，下次打开会看到 `上次中断 · 停在执行中`，产物路径也在。

整个过程我**没有打开过 DSH 自己的终端**，也没有手工复制过任何路径。

### 2.8 用户可见的业务规则

| 编号 | 规则 | 用户怎么感知 |
|---|---|---|
| **BR-01** | 一个会话同一时刻只处理一个任务 | 重复投递时看到"目标正忙"，而不是"会话不存在" |
| **BR-02** | "已接受"不等于"已完成" | 交接包显示 `已接受` 之后，状态仍是 `执行中`，直到真正产出 |
| **BR-03** | 会话状态只影响指示，不改变节点所处阶段 | 会话显示 `等待审批` 时，节点仍然在"执行中"，不会跳到"完成" |
| **BR-04** | 宿主的心跳类消息不算进展 | "执行中"不会因为命令列表刷新、用量统计这类消息而亮起 |
| **BR-05** | 会话刚建好、还没接到任务时是"空闲" | 创建后立刻显示 `空闲`，不显示 `执行中` |
| **BR-06** | 任务被取消或会话关闭后不残留 | 该会话退出"执行中"，回到 `空闲` 或从列表消失 |
| **BR-07** | 上一次任务的残留事件不影响下一次 | 连续跑两个任务，第二个的"执行中"不会因为第一个的尾巴提前亮起 |
| **BR-08** | 交接包超过等待时限未接受，标记"已过期"并要人处理 | 看到 `已过期` + "需要人工处理"，不会被静默丢掉 |
| **BR-09** | 每次状态变化都可追溯 | 事件记录里每条都有：哪个会话、什么时间、从什么状态到什么状态 |

## 三、验收标准（用户视角）

### 3.1 功能验收标准（AC）

#### AC-01 单节点任务完整跑通
- **场景类型**：主流程 ｜ **风险等级**：高 ｜ **引用规则**：BR-09
```gherkin
Given 本机 DSH 可用，且我准备了一个单节点任务
When 我执行发起命令
Then 5 秒内我看到"会话已创建"和"任务已投递"
And 状态变为"执行中"
And 任务结束后状态变为"已完成"并显示耗时
And 交接包最终状态是"已完成"
```

#### AC-02 六个会话状态各自正确
- **场景类型**：主流程 ｜ **风险等级**：高 ｜ **引用规则**：BR-05
```gherkin
Given 实例已经启动
When 会话刚创建且尚未接到任务
Then 我看到"空闲"
When 任务开始推理
Then 我看到"执行中"并带已运行时长
When 会话开始调用工具
Then 我看到"执行中 · 调用工具"并显示工具名
```

#### AC-03 等待审批时看得见
- **场景类型**：异常 ｜ **风险等级**：中 ｜ **引用规则**：BR-03
```gherkin
Given 任务执行到一个需要审批的动作
When 会话停下来等待我确认
Then 我看到"等待审批："加上被审批的动作名
And 我没有看到"执行中"
And 节点仍然显示在执行中，没有变成已完成
```

#### AC-04 交接包走完四步
- **场景类型**：主流程 ｜ **风险等级**：高 ｜ **引用规则**：BR-02、BR-09
```gherkin
Given 我发起了一个单节点任务
When 任务被投递并被目标接受
Then 交接包依次显示"已构造""已投递""已接受"并各带时间戳
When 任务产出提交
Then 交接包显示"已完成"，且时间戳晚于"已接受"
```

#### AC-05 已接受不等于已完成
- **场景类型**：边界 ｜ **风险等级**：高 ｜ **引用规则**：BR-02
```gherkin
Given 交接包已经是"已接受"
When 目标还在执行、尚未产出
Then 交接包不显示"已完成"
And 节点不显示"已完成"
```

#### AC-06 目标忙时不说会话没了
- **场景类型**：异常 ｜ **风险等级**：高 ｜ **引用规则**：BR-01
```gherkin
Given 某个会话正在执行一个任务
When 我向同一个会话再投一个任务
Then 我看到"目标正忙，本次未投递"
And 我没有看到"会话已失效"
And 原来那个任务不受影响，继续执行到结束
```

#### AC-07 会话失效时说得清
- **场景类型**：异常 ｜ **风险等级**：中 ｜ **引用规则**：BR-01
```gherkin
Given 目标会话已经被关闭
When 我向它投递任务
Then 我看到"会话已失效，需要重新创建"
And 这个提示与"目标正忙"是不同的两条
```

#### AC-08 审批被拒不吞掉原因
- **场景类型**：异常 ｜ **风险等级**：中 ｜ **引用规则**：BR-08
```gherkin
Given 任务执行到一个需要审批的动作
When 该审批被拒绝
Then 我看到"审批被拒绝"以及停在哪一步
And 交接包状态是"已拒绝"，不是"已完成"
```

#### AC-09 目标不接会过期并要人处理
- **场景类型**：异常 ｜ **风险等级**：中 ｜ **引用规则**：BR-08
```gherkin
Given 交接包已投递，但目标一直不开始执行
When 超过约定的等待时限
Then 交接包显示"已过期"
And 我看到"需要人工处理"
And 它没有被静默丢弃
```

#### AC-10 心跳消息不点亮执行中
- **场景类型**：边界 ｜ **风险等级**：高 ｜ **引用规则**：BR-04
```gherkin
Given 会话已创建但任务还没开始
When 宿主发来命令列表刷新或用量统计这类消息
Then 我看到的仍然是"空闲"
And 没有出现"执行中"
```

#### AC-11 取消后不残留
- **场景类型**：异常 ｜ **风险等级**：中 ｜ **引用规则**：BR-06
```gherkin
Given 一个任务正在执行
When 我取消这个任务
Then 该会话退出"执行中"
And 会话状态回到"空闲"或从列表消失
And 节点不会显示"已完成"
```

#### AC-12 上一次任务的尾巴不影响下一次
- **场景类型**：边界 ｜ **风险等级**：高 ｜ **引用规则**：BR-07
```gherkin
Given 我刚跑完一个任务
When 我立刻发起第二个任务
Then 第二个任务的"执行中"只由它自己的事件触发
And 第一个任务的收尾消息没有让第二个任务提前显示"执行中"
```

#### AC-13 重启后能查、但不偷偷重跑
- **场景类型**：边界 ｜ **风险等级**：高 ｜ **引用规则**：BR-09
```gherkin
Given 一个任务跑到一半时我关掉了进程
When 我重新打开并查看实例状态
Then 我看到上次的节点、会话、交接包状态与完整事件记录
And 未完成的任务标记为"上次中断"
And 系统没有自动重新执行这个任务
```

### 3.2 非功能验收标准

| 编号 | 我作为用户能感知的约束 | 目标 |
|---|---|---|
| NFR-01 | 发出任务后多久看到"执行中" | 5 秒内（DSH 已预热） |
| NFR-02 | 会话状态变化多久反映到我能看到的地方 | 1 秒内 |
| NFR-03 | 连续跑 10 个任务，状态会不会错乱或丢事件 | 0 次错乱、0 条丢失 |
| NFR-04 | 重启后能不能查全上次的状态 | 节点 / 会话 / 交接包 / 事件 4 项齐全 |
| NFR-05 | 出问题时能不能顺着时间线复盘 | 每次状态变化都有一条带时间戳的记录 |
| NFR-06 | 中断后重开，会不会偷偷重跑导致重复干活 | 不会自动重跑 |
| NFR-07 | 关掉查看用的终端，正在跑的任务会不会被带走 | 不会（任务进程独立于查看终端） |

### 3.3 验收前置条件

- 本机已安装 DSH 并能启动（阶段零已打通：CLI `0.2.1-rc.5` + `dsh-acp-server` `0.14.4`）
- 存在一个可用的模型来源：真实凭据，或包内确定性 mock LLM（用 mock 时只能验证链路与状态，**不代表真实推理质量**，验收报告需注明用的哪种）
- 有一个单节点任务样例，写明任务描述与预期产物路径
- `.orch/` 目录可写，且当前没有残留的旧实例干扰
- 验收时能对照 DSH 自身的输出来核对状态是否标错

### A. 术语表

| 术语 | 含义 |
|---|---|
| 节点 | 编排单位，一个"要做的事"。本迭代只有 1 个 |
| 会话 | 执行单位，一个跑在宿主里的对话。一个节点对应一个会话 |
| 交接包 | 把"要做什么、依据是什么"从一个角色传给另一个角色的结构化包裹 |
| 归一化 | 把宿主五花八门的事件翻译成统一的 6 个会话状态 |
| 心跳类消息 | 宿主定时发的状态刷新（命令列表、用量统计），不代表任务有进展 |
| 已接受 / 已完成 | 前者=对方开始干了，后者=对方干完了。两者差着一整个执行过程 |
