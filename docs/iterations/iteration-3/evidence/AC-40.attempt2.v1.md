# DevKit v1.2.0 发布说明

> 适用对象：已在项目或 CI 中使用 DevKit v1.x 的开发者
> 目标版本：v1.2.0
> 上一稳定版：v1.1.4

DevKit v1.2.0 主要围绕三件事：减少重复构建、让运行过程更可观测、把配置问题提前到本地和 CI 暴露。本版本包含少量不兼容变更，升级前请先阅读「升级步骤」中的前置条件。

## 新功能

### 增量构建与内容寻址缓存

`devkit build` 在 v1.2.0 中默认启用增量构建和内容寻址缓存：只重建受影响的模块，重复构建直接复用已有结果，减少本地和 CI 的重复工作。

- 缓存目录：`.devkit/cache/v2`
- 缓存键包含：锁文件、构建配置、DevKit 版本
- 需要绕过缓存排查问题时，使用 `--no-cache`

```bash
# 默认使用增量构建与缓存
devkit build

# 跳过缓存，用于排查缓存相关问题
devkit build --no-cache
```

注意：

- 升级后 v1.1.x 的旧缓存不会命中，会按需重建，不需要手工迁移缓存。
- CI 如需跨任务复用缓存，请持久化 `.devkit/cache/v2`，并让缓存键包含锁文件哈希、配置哈希和 Node.js 大版本。
- 不同分支或不同 Node.js 大版本建议使用不同的缓存命名空间，避免缓存相互污染。
- 实际收益取决于项目结构、变更范围和缓存命中情况，本文不给出固定比例。

### 结构化日志与 OpenTelemetry 导出

`--log-format json` 将每条日志输出为一行 JSON，便于日志系统按字段检索；设置 `DEVKIT_OTLP_ENDPOINT` 后，`devkit run` 会把 trace/span 导出到兼容 OTLP/HTTP 的采集端。默认仍为人类可读文本，不改变现有输出习惯。

```bash
# JSON 日志
devkit run --log-format json

# 导出 trace/span（Bash）
DEVKIT_OTLP_ENDPOINT=http://localhost:4318 devkit run
```

PowerShell 中设置环境变量：

```powershell
$env:DEVKIT_OTLP_ENDPOINT = "http://localhost:4318"
devkit run
```

注意：

- 敏感字段默认脱敏；自定义字段不要写入密钥、令牌或个人信息。
- 接入前确认采集端支持 OTLP/HTTP，并按团队规范配置采样与保留策略。
- 建议只在需要的环境启用导出，通过环境变量或 CI 配置控制，不要写死在共享配置中。
- 导出失败时的处理行为以实际实现为准，接入前请在测试环境验证。

### 配置校验与迁移命令

新增两个配置相关命令：

- `devkit config validate`：校验语法、字段名和值类型，报错包含文件、行号和修复建议。
- `devkit config migrate`：将 v1.1 的配置迁移到 v1.2.0 结构。

`--strict` 会把未知字段视为错误，建议在 CI 中启用。

```bash
# 基础校验
devkit config validate

# 严格校验（建议在 CI 使用）
devkit config validate --strict

# 预览迁移改动
devkit config migrate --from 1.1 --dry-run

# 确认后写入
devkit config migrate --from 1.1 --write
```

注意：

- 先 `--dry-run` 再 `--write`；执行前确认配置已提交或备份。
- 迁移会重写配置文件，完成后必须 review diff，不要直接接受全部改动。
- 历史遗留字段较多的项目，可以先不加 `--strict` 完成清理，再在 CI 中启用严格校验。

### 可配置的重试与超时策略

新增 `network.timeoutMs`、`network.retry.maxAttempts`、`network.retry.backoffMs` 三个配置项，用于应对网络抖动或依赖服务短暂不可用。默认值与 v1.1.x 保持一致，只有显式配置才会改变行为。

```yaml
network:
  timeoutMs: 30000
  retry:
    maxAttempts: 3
    backoffMs: 500
```

注意：

- 默认只对幂等请求重试；非幂等操作需要显式开启，不要理解为“所有请求都会重试”。
- 重试表示允许再次尝试，不保证请求最终成功。
- `backoffMs` 是退避基准值，请结合依赖服务的承载能力设置，避免集中重试放大压力。

### 其他改进

- 更新了部分依赖与文档。
- 修复了若干在 v1.1.x 中反馈的问题。
- 详细条目请以代码仓库的变更记录为准。

## 升级步骤

v1.2.0 的升级路径为 v1.1.x → v1.2.0。以下命令在依赖安装部分给出 npm、pnpm、yarn 三种写法，其余命令如无特别说明均以 `devkit` CLI 为准。

### 1. 升级前准备

1. 从最新 v1.1.x 拉出升级分支，确认工作区干净，便于 review 和定位问题。
2. 备份 `devkit.config.*`、锁文件、CI 配置和当前构建产物，便于对比和排查。
3. 记录当前版本与提交：

   ```bash
   devkit --version
   git rev-parse HEAD
   ```

4. 确认 Node.js 版本：

   ```bash
   node --version
   ```

   v1.2.0 最低要求 Node.js 18.17，建议使用 Node.js 20 LTS。

5. 核对本版本的不兼容变更：

   - Node.js 16 不再支持，最低要求 18.17。
   - 缓存目录从 `.devkit/cache` 变为 `.devkit/cache/v2`。
   - 部分旧配置键被弃用，需要通过迁移命令处理。
   - 本次发布不包含持久化数据或服务端 schema 迁移。

### 2. 升级依赖

按项目使用的包管理器选择一种，版本统一为 `1.2.0`：

```bash
# npm
npm install -D devkit@1.2.0

# pnpm
pnpm add -D devkit@1.2.0

# yarn
yarn add -D devkit@1.2.0
```

- 若项目直接依赖多个 DevKit 子包，请全部对齐到 `1.2.0`，避免版本混用。
- 安装后检查依赖树：

  ```bash
  npm ls devkit
  ```

- 使用 pnpm 或 yarn 时，对应执行 `pnpm list devkit` 或 `yarn why devkit`。

### 3. 迁移配置

```bash
# 1) 预览迁移内容
devkit config migrate --from 1.1 --dry-run

# 2) 确认后写入
devkit config migrate --from 1.1 --write

# 3) 严格校验
devkit config validate --strict
```

迁移后重点 review：

- 被重命名或删除的字段是否符合预期；
- 新增字段的默认值是否适合当前项目；
- 是否存在仅为兼容历史环境而保留的临时配置。

若 `--strict` 报未知字段，按提示删除或替换；不确定的字段先查迁移说明，不要直接忽略。

### 4. 更新 CI

- 将 CI 的 Node.js 版本改为 18.17+，建议 20 LTS。
- 缓存路径改为 `.devkit/cache/v2`，缓存键包含锁文件哈希、配置哈希和 Node.js 大版本。
- 在流水线中加入配置校验和构建检查：

  ```bash
  devkit config validate --strict
  devkit build --check
  ```

- 固定版本镜像要更新 tag，避免“本地已升级、CI 仍拉取旧版”。
- 使用冻结安装：`npm ci`、`pnpm install --frozen-lockfile` 或 `yarn install --immutable`。

GitHub Actions 示例（可按实际 CI 替换）：

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: 20
    cache: npm

- run: npm ci
- run: npx devkit config validate --strict
- run: npx devkit build --check
```

如需跨任务复用构建缓存：

```yaml
- uses: actions/cache@v4
  with:
    path: .devkit/cache/v2
    key: devkit-${{ runner.os }}-node20-${{ hashFiles('**/package-lock.json', 'devkit.config.*') }}
```

### 5. 本地验证

```bash
devkit doctor
devkit build
npm test
```

验证清单：

- [ ] `devkit --version` 输出 `1.2.0`
- [ ] `devkit doctor` 无 error
- [ ] `devkit config validate --strict` 通过
- [ ] 构建成功，产物与 v1.1.4 对比无意外差异
- [ ] 关键测试通过
- [ ] 启用 JSON 日志时，日志可被正常解析
- [ ] 启用 OTLP 导出时，采集端能看到对应的 trace/span

建议将升级分支的 CI 结果与 v1.1.4 基线对比，确认构建成功率、耗时和错误率没有明显异常。

### 6. 分阶段发布与观察

1. 先发布到测试环境或内部 dogfood 环境，完成一轮完整构建和关键链路验证。
2. 再按 5% → 25% → 50% → 100% 逐步放量；比例和节奏按实际发布系统调整。
3. 每个阶段观察构建成功率、错误率、P95 耗时和关键业务指标，至少覆盖一个发布窗口。
4. 指标正常后再进入下一阶段；全量稳定后结束本次发布观察。

### 7. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `ERR_DEVKIT_NODE_VERSION` | Node.js 低于 18.17 | 升级 Node.js，或用版本管理器切换 |
| `ERR_DEVKIT_CONFIG_UNKNOWN_KEY` | `--strict` 下存在旧字段 | 运行迁移命令，或按提示删除、替换 |
| 缓存命中异常 | 缓存目录或缓存键变更 | 清理 `.devkit/cache/v2` 后重新构建 |
| CI 仍使用旧版 | 镜像 tag 或锁文件未更新 | 更新镜像 tag，确认锁文件已提交并使用冻结安装 |

升级中遇到未覆盖的问题，请附上 `devkit --version`、`devkit doctor` 输出和最小复现步骤，提交到项目 issue 跟踪器。
