## D-AC40-1 审核提示词只给相对路径，真实模型把 `out/review.json` 写进实例工作区，核心只读任务目录

- **严重度**：P1（真实面稳定性；2/3 次尝试失败，第 3 次才通过）
- **规格依据**：`docs/iterations/iteration-3/requirement.md`
  - 第 386 行：「`.orch/` 与实例工作区跟着**项目根**走，`out/review.json` 跟着 `--cwd` 的**任务目录**走」
  - C-03（第 112 行）：「审核文件固定为任务目录相对的 `out/review.json`」
  - BR-33（第 595 行）：「审核文件是唯一例外：固定读**任务目录**下的 `out/review.json`」
- **结论**：核心的**读取根**符合规格；缺陷在**提示词**——它同时给出「工作区：<绝对路径>」和「审核文件写入路径：out/review.json（裸相对路径）」，没有说明相对谁，真实模型按最近的上文（工作区）拼路径。

### 现象

第 1、2 次尝试：

- 模型（T-003 审核者）把 `review.json` 写到
  `<项目根>/.orch/instances/INST-001/workspace/out/review.json`
- 核心到 `<任务目录>/out/review.json` 读，读不到 →
  `review.invalid`（`reasonCode=review_missing`）→ 升级挂起，`orch run` 退出码 4
- 两个目录的实测状态：`demo-doc-real/out/` 不存在；`workspace/out/review.json` 存在且内容为合法 reject

第 3 次尝试（同一命令、同一任务原文、全新项目根）：模型两轮都直接写到
`<任务目录>/out/review.json`，全链跑通。→ **同一提示词下模型行为不稳定**。

### 最小复现

```bash
# 1) 全新项目根 + 真实 DSH host 配置（launch.env 指向隔离 DSH_HOME）
# 2) 发起
cd <项目根>
node D:/WWW/Maestro/bin/orch.js run --cwd ./demo-doc-real --template task-loop \
  --task "写一篇发布说明，面向使用 v1.2 的开发者，必须包含「新功能」「升级步骤」「回滚方案」三节。
第 1 轮先只写「新功能」与「升级步骤」，故意不要写「回滚方案」；审核会驳回，第 2 轮再补上「回滚方案」。
产物：release-notes.md"
# 3) 观察审核者回合结束后
ls ./.orch/instances/INST-001/workspace/out/review.json   # 存在
ls ./demo-doc-real/out/review.json                        # 不存在
```

复现率：3 次中 2 次（attempt 1、attempt 2）。

### 实际下发的审核提示词（attempt 3，`AC-40.prompt.review.txt`）

```
…（任务原文）…

本轮文档引用：artifacts/docs/release-notes.v1.md

只认审核文件：{"decision":"pass"|"reject", …}
```

对比：撰写者拿到的 `写入路径：` 是**绝对路径**（`writePathOf(workspaceDir, ref)`），审核者拿到的却是裸相对路径。

### 疑似位置

| 位置 | 现状 |
|---|---|
| `src/templates/index.js:118` | `review` 提示词模板：`工作区：{workspaceDir}` + `审核文件写入路径：{reviewPath}`，`{reviewPath}` 无基址 |
| `src/core/orchestrator.js:1192-1220` | 组装提示词时传了 `workspaceDir`，但 `reviewPath` 仍走 `target.reviewPath`（`'out/review.json'`） |
| `src/core/review.js:248-249` | `const baseDir = path.resolve(cwd ?? '.'); const absPath = path.join(baseDir, REVIEW_PATH);` —— 读任务目录，符合 C-03 |

### 建议修法（未实施）

二选一，均只动提示词/组装点，不动读取根：

1. **给绝对路径**（与撰写者对齐）：组装时传
   `reviewPath: path.join(state.cwd, REVIEW_PATH)`（posix 分隔符），模板保持原文；
   或在模板里写 `审核文件写入路径：{reviewWritePath}` 并在 `promptFor` 里填绝对路径。
2. **显式写明基址**：模板改为
   `审核文件写入路径：<任务目录绝对路径>/out/review.json（相对任务目录，不是工作区）`。

修完必须重跑 AC-40 ≥3 次，确认 `review_missing` 不再出现；注意 AC-39 断言
`review.read` 的 `detail.path` 仍是 `'out/review.json'`（本项与提示词无关，不应改动）。
