# Maestro 桌面 UI v2 · 页面清单与交互规范

> 依据：`docs/index.md` 第一部分能力域 5（实例管理四层视图）、能力域 6（治理与审计）、
> 第二阶段规划 I1.10a / I1.10b / I1.11 / I1.12。本清单是「阶段一全部能力在桌面端可操作」的页面基线，
> 也是 beta.2 的验收口径：每一行都必须有可点击入口，且不依赖 CLI。

## 一、信息架构（三层 + 全局）

```
全局层  项目选择 → 实例列表
                  ├─ 审批/升级队列（跨实例）
                  ├─ 通知中心
                  ├─ 资产库（角色 / 技能 / 工作流）
                  ├─ 角色占用（全局资源）
                  ├─ 工作流画布（定义态只读）
                  ├─ 治理与审计
                  └─ 设置
实例层  实例工作区（概览 / 流程图 / 节点看板 / 审批队列 / 证据）
        └─ 角色下钻层（角色状态栏 + 局部 DAG + 任务卡片）
              └─ 节点详情层（抽屉：会话时间线 / ACP 摘要 / 证据 / 交接历史 / 跳转宿主）
              └─ 交接包面板（抽屉：7 状态 + 时间线）
              └─ 升级面板（抽屉：继续 / 重派 / 终止）
              └─ 子工作流（折叠组下钻）
```

设计约束：
1. **下钻不跳页**：节点详情、交接包、升级处理一律右侧抽屉，关闭后回到原滚动位置与展开态。
2. **每个视图三态齐全**：loading / empty / error（error 必须给原因与重试），不允许空白页。
3. **状态即信息**：健康度、节点状态、角色状态、交接状态用统一徽章语义，颜色不混用。
4. **可返回**：`Esc` 关抽屉，`←` 回上一层，浏览器式返回栈，URL（hash）可复现当前位置。
5. **零中文字面量**：`desktop/ui/**` 不写中文，全部经 `/ui/labels` 下发键取值。

## 三、关键交互规范

### 3.1 流程图
- 单击角色节点 → 角色下钻（保留缩放/平移，返回时逐字恢复）
- 单击特殊节点：`human` → 节点详情；`escalate` → 升级面板；`subworkflow` → 子工作流
- 单击连接线 → 交接包面板；悬停节点 → 高亮上下游，其他降透明
- 滚轮缩放（0.4~2.4）、拖拽平移、双击聚焦 2 跳、折叠分组、手动拖拽位置按实例保存
- 异常角色角标 + 脉冲，不改变节点尺寸

### 3.2 角色下钻与卡片
- 左 DAG 节点颜色 = 节点状态；该角色加粗边框；点击节点 → 右列表滚动到对应卡片并高亮
- 卡片三层：标题（节点 ID · 标题 · 轮次）/ 执行（角色 · 会话状态 · 耗时 · 当前工具）/ 依赖产出证据
- 卡片点击 → 节点详情抽屉；`查看全部节点` → 看板（返回回到下钻而非流程图）

### 3.3 队列与审批
- 每项可执行动作必须来自投影的 `actions`，禁用动作给出原因提示
- 终止类动作二次确认；处理后就地显示结论，不刷新整页
- 失败保留原内容并给重试，不显示栈

### 3.4 证据
- 左侧按节点分组；右侧命令、退出码、产物引用、摘要
- 超过渲染上限截断并显式提示，可导出原文件

### 3.5 空/错/载入
| 场景 | 表现 |
|---|---|
| 连接中 | 骨架 + 「正在连接守护进程…」 |
| 断开 | 顶部通知条 + 保留最后内容 + 重试 |
| 无实例 | 空态卡 + 「新建实例」主行动 |
| 读取失败 | 错误行（原因）+ 重试 + 返回列表 |
| 无权限/不可读 | 明确「不可读」而不是空 |

## 四、与现有实现的差距（实现清单）

1. `paint()` 缺 `drill / node-detail / escalation-panel / connection-panel / subflow` 分支 → 下钻算出来不渲染。
2. 图节点、卡片、连接线、角色行没有点击绑定 → 只能靠 `__MAESTRO_CTL__` 验收钩子驱动。
3. 无路由/返回栈/滚动与展开态保留。
4. 队列、资产、占用、画布、证据渲染过于朴素（纯文本行、`<pre>`、边标签画在 (0,0)）。
5. 缺资产库、占用、画布、治理、设置、命令面板的入口与渲染。
6. 首屏项目页只有一个 logo + 一行提示，无可选项目。

以上 1~6 为 beta.2 的实现范围；CLI 专属能力（包导入导出、`orch migrate`）在治理页以只读状态与命令提示呈现。
