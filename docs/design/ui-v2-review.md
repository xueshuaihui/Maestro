## 2. 端到端流程走查

六条主流程逐跳走查，每一跳都确认「有入口 / 有反馈 / 有退路」：

1. **冷启动 → 选项目 → 看列表**
   首屏无项目时落项目选择页（不是空列表），「选择项目」调原生目录对话框，
   绑定成功后整页重载进列表。失败保留当前页，连接行显示原因。
2. **新建实例 → 跑起来 → 看到它**
   列表页右上 `+ 新建` → 新建页选工作流（卡片高亮）→ 填任务 → 开始。
   提交成功自动回列表，新行由 `instances.changed` 推送出现（AC-04）。
   校验失败在表单内联报错，不弹窗、不清空已填内容。
3. **实例 → 概览 → 流程图 → 下钻 → 处置 → 回退**
   概览给阶段/待处置/节点进度/健康度四张卡 + 时间线 + 下一步；
   流程图按后端坐标画 SVG，点节点进下钻、点边进连接详情、点特殊节点进子工作流；
   下钻页给角色栏 + 局部 DAG + 卡片，卡片可继续钻；
   升级卡片在抽屉里直接处置，处置后抽屉不关、行状态就地刷新；
   `←` 或面包屑回退，返回栈记录跳转历史。
4. **队列 → 逐条处置**
   七列视图 + 逐行「重派 / 通过 / 驳回 / 取消（两步确认）」；
   处置结果以 toast + 行内结论双通道反馈，已处置行不消失但置灰。
5. **异常 → 恢复**
   连接断开：顶栏状态点 + 内容保留（不白屏）+ 重试按钮；
   图加载失败：空态里给重试与返回；实例不可读：该行标注「状态不可读」，其余行照常。
6. **全局检索与跳转**
   ⌘K 打开命令面板，可跳任一页面/实例；通知点开进通知中心，点条目跳到对应队列行。

结论：六条流程均可闭合，没有「点进去出不来」的路径。

## 3. 本轮发现并修复的问题

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 侧栏点「治理审计 / 设置 / 通知中心」无反应 | `setView()` 白名单只含 I1.11 五个视图 | 放开 beta.2 新增视图 |
| 2 | 新建页选工作流不生效、填的任务提交不上 | 页面读 `newForm`，真实状态在 `newPanel` | 统一读 `model.panel` |
| 3 | 提交成功后停在空白表单，无任何反馈 | 成功分支只关面板，不换页 | 成功回列表页，并用推送补行 |
| 4 | 流程图 / 看板加载失败后无出路 | 空态只有一个占位符 | 空态补「重试」与「返回」 |
| 5 | 治理审计表恒为空 | `rows` 只在 `instances` 视图计算 | `rows` 改为所有视图共用同一投影 |
| 6 | 队列徽章重算 pending 计数 | 违反 D-36「界面零计数」 | 直接取投影条目数 |
| 7 | 实例列表无法只看待处置 | 筛选只有状态维度 | 新增「待处置」筛选 |
| 8 | **真实窗口一片空白、列表永远是空** | `mountApp` 内 10 处引用了 `createApp` 作用域的 `noticeText`，首帧 `ReferenceError` → `mountApp` 抛出 → `index.html` 的 `app.start()` 从未执行 → 文案表永远不加载 | 由 `createApp.text()` 统一出口；新增 `test/wp14/mount-smoke.test.js` 真正调用 `mountApp` |

第 8 条是这一轮最有价值的发现，值得单独说明：

- 它**只在真实窗口里出现**。`createApp` 级测试全部绿灯，界面冒烟脚本是手工构造上下文直接调
  `renderShell`，两者都不经过 `mountApp`——而真实窗口只走 `mountApp`。
- 它**在 Windows 门禁上不暴露**：那里 `AC-26` 因 bundle 不新鲜被判 skip，
  「Windows 过」等于没验证真实壳。只有 macOS 门禁真的开了窗口。
- 定位靠的是新加的诊断探针：`rows-empty{ready:false, labels:0, instances:2, status:"idle"}`
  ——实例读得到、文案表永远为空、连接状态还停在 idle，三条合起来才能推出「`start()` 没跑」。
- 教训：入口层没有被测试真正调用时，等于把整条链路交给 CI 去发现。

每条都有对应回归：`test/wp14/mount-smoke.test.js`（挂载 / 探针 / 侧栏无死链）、
`test/wp13/errors.test.js`（R-06）、`test/wp14/ui-views.test.js`（setView）、
`test/wp14/contract.test.js`（D-36 / AC-43 / A-11）、`test/wp13/labels-desktop.test.js`（文案键）。

### 3.1 真机验证追加（beta.2 装机后反馈「侧栏有时候切不动」）

前 8 条是代码走查 + CI 探针找到的。用户装上 beta.2 后反馈「侧栏切换有时候没反应」，
于是改用**直连真实窗口**的方式验证：给 WebView2 开远程调试端口，用 CDP 在真实窗口里
派发真实鼠标事件、读 DOM、截图。这条路径能测到测试环境永远测不到的东西。

| # | 现象（真机复现） | 根因 | 修复 |
|---|---|---|---|
| 9 | 点侧栏「项目」**永远**没反应 | 侧栏项的 `data-arg` 是 `projects`，视图名是 `project`，`setView()` 不认 | 统一为 `project` |
| 10 | 侧栏/顶栏**有时候**点了没反应 | `paintSidebar`/`paintTopbar` 每次重绘 `clear()` 后重建全部按钮；实例 SSE 每帧都触发 `paint()`，按下与抬起跨帧时浏览器不派发 `click` | 骨架复用（按 key 更新，不重建）+ 实时帧 90ms 合并 + 导航类动作 `pointerdown` 即响应 |
| 11 | 品牌位显示成「实例」 | 品牌名取了 `instancesLabel` | 固定产品名 `Maestro` |
| 12 | 左下角项目卡片下多一个无文字圆点 | `hidden` 被模块自己的 `display:flex` 覆盖 | 改用 `style.display`，并给正常连接补「已连接」 |
| 13 | 治理页「链式哈希」显示成「状态」 | 指标值传了 `DESKTOP_V2_STATE` 文案键 | 四个治理指标无数据源时显示 `—` 并说明来源，不再拿健康度凑数 |
| 14 | 设置页「通知」卡片恒为「暂无数据」 | `prefs` 只在 `view === 'queue'` 时组装 | `prefs` 提到全视图公共投影，设置页与队列页读同一份 |
| 15 | 设置页「返回」点了没反应 | 同第 9 条，`nav arg=projects` | 改为「切换项目」，去掉重复入口 |
| 16 | 项目页只有「重试 / 项目」两个按钮 | 页面按「项目阻塞」写死，正常状态没有分支 | 正常时显示项目路径、数据目录与「切换项目 / 实例」 |
| 17 | 实例空态里同一动作出现两次 | 主区空态按钮 + 右栏卡片 | 空态只保留说明，创建入口留在右栏 |
| 18 | 「待处理 无」「角色占用 无」 | 文案键值本身是两段拼接 | 改为「暂无待处理项」「暂无角色占用」 |
| 19 | 画布页无法切换工作流；节点表「状态」列显示角色名；角色名是 `worker` 之类英文 | 缺选择器、列名错配、`ROLE_LABEL` 未下发 | 加模板 chips；列名改「详情」；`ROLE_LABEL` 并入下发全集 |
| 20 | 通知页右上按钮叫「关闭」 | 动作是 `read-all`，文案用错键 | 改「全部标记已读」，空列表时禁用 |

第 10 条是用户感知最强的那个「有时候」，机制值得记下来：

```
mousedown → [SSE 帧到达 → paint() → clear(sidebar) + 重建按钮] → mouseup
```

浏览器只在按下与抬起解析到**同一个节点**时才派发 `click`。所以这不是「事件没绑上」，
而是「绑的那个节点在按下之后被换掉了」。它天然是概率性的——帧越密、机器越忙越容易撞上，
这也解释了为什么代码审查和单元测试都发现不了，只有真机连点才复现。

真机验证口径（可复跑）：

| 项 | 方法 | 结果 |
|---|---|---|
| 侧栏九项切换 | CDP `Input.dispatchMouseEvent` 逐项真实点击，读 `.nav-item.on` 与 `h1` | 9/9 通过，零异常 |
| 快速连点 | 9 项 × 3 轮，间隔仅 60ms（刻意让重绘落在下一次按下里） | 27 次点击 0 失败 |
| 命令面板 | `Ctrl+K` → 输入「设置」→ 回车 | 打开、过滤到 1 项、跳转并关闭面板 |
| 新建表单 | 进新建页 → 选「编码闭环」→ 输入任务 | 选中态与输入值都保留，提交按钮可用 |
| 画布切换 | 依次点三个模板 chip | 1 节点 → 2 节点/3 边 → 3 节点/4 边，标题与表格同步 |
| 运行时异常 | 全程挂 `window.onerror` 收集 | 0 条 |

## 4. 已知边界（未在本轮解决，需知情）

1. **本机无法构建桌面二进制**（无 Rust / MSVC / Windows SDK）：真实壳的自动取证已在 CI 完成
   （AC-26 在 macOS 上真实开窗并通过），但「装上手的观感」仍需安装后确认——这属于人的判断，
   自动化测试给不了答案。
2. **项目选择依赖原生对话框**：Web 预览下「选择项目」无效果，属预期（`pick_project` 只在 Tauri 内可用）。
3. **全局搜索 = 导航跳转**，不做实例/节点的全文检索；PRD 未要求，但若后续要「搜任务内容」需新增后端接口。
4. **证据视图只读**：可看、可复制、可定位到节点，但不支持在界面里补录证据。
5. **角色 / 技能库在空项目下是 0 条**：这两类资产来自项目目录里的角色与技能定义文件，
   内置模板的角色没有单独落盘。页面现在会说明这一点，不伪造成有数据；要看到条目需先有
   `roles/`、`skills/` 定义或导入。
6. **单节点模板的节点角色 `worker` 没有中文名**：`ROLE_LABEL` 只覆盖六个模板角色，
   画布「详情」列对未收录的角色 id 显示原名。

## 5. 回归结论

发布门禁（CI run `45043664056`，三平台 + 汇总全 success）的实测数字：

| 平台 | tests | pass | fail | 判定 |
|---|---|---|---|---|
| macOS x64（严格面：无平台豁免） | 1932 | 1926 | 4 | 4 条全落在 9 条判定基线内，差集 0 |
| macOS arm64 | 1932 | 1926 | 4 | 同上 |
| Windows x64 | 1932 | 1903 | 16 | 16 条全落在 25 条判定基线内（含 16 条 win32 平台敏感项） |

补充口径：

- **新增红 = 0**。macOS 严格面只剩 4 条历史基线项（`readReview` p95、`verifyProducts` p95、
  `core.stop` 收敛、`cursor.json` 并发消费一类时序/性能断言），与 beta.1 一致。
- 本地串行复核（12 个失败文件，`--test-concurrency=1`）：**118 例 / 102 通过 / 14 失败**，
  对照 `f201cb2` 基线树同命令 **118 例 / 103 通过 / 13 失败**，差值为 1 条
  `AC-23 #3`（`git diff HEAD` 型用例，提交后转绿，已复核）。
- 并发跑全量会额外造 5 条负载型 flake（三主链、AC-34、AC-62、openHost 500ms、EBUSY），
  串行复跑全绿——判 flake 前必须串行证伪。
- purity 门禁：`src/core,src/daemon` 对图/角色字面量零命中。
- 界面冒烟：19 页 + 3 抽屉在 DOM shim 下全部渲染出非空内容。
- 挂载链路：`test/wp14/mount-smoke.test.js` 3 例——空文案表首帧不抛、行探针正常发出、
  侧栏九项 + 「新建实例」全部可达。
- 文案键 312 → 365（+53，全部 `DESKTOP_V2_` 前缀，既有键值一字未改）。
- 发布产物：`Maestro_0.0.1-beta.2_x64.dmg`、`_arm64.dmg`、`_win-x64-setup.exe` + `SHA256SUMS.txt`，
  三条校验和与资产 digest 逐条相等；Release `draft=false / prerelease=true`，匿名访问 HTTP 200。
